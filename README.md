# Swift Evolution Karuta Online

Swift Evolution の4択カルタを、進行役・会場ディスプレイ・参加者のスマートフォンで遊ぶ Web アプリ。略称は **SE Karuta**。

React + Cloudflare Workers / Durable Objects / D1。現在はローカルで試遊する初期実装です。Cloudflare の本番リソースは作成・変更していません。

## ローカル起動

Node.js 22.22 以上を用意し、プロジェクトのルートで実行します。

```sh
npm ci
npm run setup
npm run dev
```

`setup` は `.dev.vars` がなければ作成し、ローカル D1 にマイグレーションを適用します。既存設定や大会は削除しません。管理用パスワードの初期値は `local-karuta`、セッション署名鍵はランダムに生成します。

[http://localhost:5218](http://localhost:5218) を開きます。ポート **5218** は、サンプル問題の **SE-0218 (compactMapValues)** にちなんでいます。使用中なら別ポートへ自動で変更せずエラーにします。

別のターミナルで、試遊用の3問を登録できます。

```sh
npm run seed
```

作成した大会の Control / Display / Player の URL が表示されます。試遊大会の Display 用パスワードは `display-karuta`。コマンドを再実行すると別の大会を作成します。管理画面から独自の問題 JSON を登録することもできます。

## スマートフォンで試す・公開URLを設定する

`.dev.vars` の `PUBLIC_ORIGIN` に、**スキーム・ホスト・ポートを含む公開元URL**を指定します。パスは付けません。

```dotenv
PUBLIC_ORIGIN=http://192.168.1.2:5218
```

変更後、サーバーを再起動します。

```sh
npm run dev
```

同じネットワークのスマートフォンで [http://192.168.1.2:5218](http://192.168.1.2:5218) を開くか、Control / Display の QR コードを読み取ります。IP アドレスは使用するマシンに合わせて変更してください。

- 参加用 QR コード・画面リンクはサーバーが `PUBLIC_ORIGIN` から生成します。リクエストの `Host` / `X-Forwarded-Host` から推測しません。
- 別のホスト名から開いた画面は、設定された公開URLへ移動します。WebSocket の接続先と操作の Origin 検証も同じ設定を使います。
- ホスト名を変更するとブラウザーの Cookie が別扱いになるため、進行役・Display は再ログイン、参加者は再登録になります。大会を始める前に URL を固定してください。
- `dev` はローカル開発サーバーを LAN に公開します。会場の Wi-Fi が端末間通信を制限している場合は接続できません。
- `seed` の通信先は既定でループバックです。表示するURLと Origin ヘッダーには設定値を使います。ポート自体を変えるときは `vite.config.ts` と `PUBLIC_ORIGIN` を揃え、`LOCAL_URL=http://localhost:新ポート npm run seed` とします。

本番では Workers の環境変数に `PUBLIC_ORIGIN=https://公開ホスト名` を設定する設計です。実際の本番構築・ドメイン設定・秘密値の登録は未実施です。

## 遊び方

1. Control で次の問題・正解・解説を事前確認し、Display を会場画面で開きます。
2. 参加者は QR コードから名前を登録します。
3. 「全員の準備確認を開始」を押します。選択肢は伏せ、「全員の接続を待っています」と準備完了人数 / 対象人数を表示します。
4. 準備できない人は Control でその問題だけお休みにできます。全員と会場 Display が揃ったら、公開前5秒 → 選択肢公開・出題まで15秒 → 問題公開・回答受付15秒 → 自動締切と進みます。各カウントダウンには残り秒数と横長バーを表示します。
5. 締切で問題文を隠し、未回答者は「回答なし」になります。Control で正解・先着順位を順に公開して次の問題へ進みます。早期の手動締切もできます。
6. 終了すると正答王・早押し王・安定王・難問王の結果を表示します。

問題文は共有 Display に表示し、参加者は4つの選択肢から回答します。回答は1問1回で変更できません。通信切断時は自動再接続し、回答を再送しても最初に保存した回答を維持します。お休みは次問で解除され、途中参加者も次問から対象になります。問題を無効化すると全表彰の集計から除外します。

3つの時間は大会ごとに保存します。Control の「時間の設定」で各1〜600秒の整数に変更でき、進行中の期限は維持して次に始まる段階から反映します。次問では前問の選択状態もクリアします。

準備完了通知は待機画面の DOM 反映・描画機会・タブの可視状態に基づきます。選択肢は公開前カウントダウン終了後に配信します。人間が実際に読んだことや端末間の完全な同時表示を保証するものではありません。複数 Display がある場合、Control で指定した1台を待ち合わせ対象にします。接続が切れた Display の差し替えは出題前の待機中に行います。

開発中に `src/worker/` のコードを変更した場合は、開発サーバーを再起動してください。ホットリロードで既存 WebSocket とタイマーの状態がずれる場合があります。通常の大会進行ではページのリロードは不要です。

## 問題データ

[`data/questions/demo.json`](data/questions/demo.json) を参考にします。`id`、`bodyMarkdown`、A〜D の `choices`、`correctChoice`、`explanationMarkdown` を持つ配列です。CLI は `questions` プロパティで包んだ形式も読み込みます。問題数は1〜100問、各文字数・ID重複・選択肢数を検証します。

```sh
npm run questions:check
npm run questions:check -- path/to/questions.json
```

問題・正解をクライアントの静的ファイルへ含めず、役割と進行段階に応じたデータだけを WebSocket で送ります。大会作成時に JSON を取り込みます。本番で使う問題セットは別途レビューしてください。

## 問題ビューワ

トップ画面または Control の「問題ビューワ」から `/questions` を開きます。管理用パスワードは大会管理と共通です。

1. 大会を選んで「大会から読み込む」、または問題 JSON をファイル選択・貼り付けで開きます。
2. 一覧・検索・前後ボタンで問題文・選択肢・正解・解説を確認します。正解の表示、暗い背景を切り替えられます。
3. 「この問題を調整する」を開いて編集すると、すぐにプレビューへ反映されます。
4. 「JSONをダウンロード」で保存し、次の大会作成時に取り込みます。

「Displayプレビューを開く」で、本番Displayと同じレイアウトを別タブに表示できます。普通のリンクなので、ブラウザーの操作で別ウィンドウにも開けます。問題の選択・編集は自動で反映され、「出題中」（初期状態）・「選択肢公開」・「正解発表」を切り替えられます。タイマーは15秒で固定し、ウィンドウを会場の画面サイズに合わせて、コードや選択肢の収まりを確認できます。大会への接続や登録は行いません。ビューワを閉じる・別ページへ移動すると、プレビューは案内表示に戻ります。

編集内容は画面内にだけ保持します。元ファイルと既存大会は変わりません。ダウンロード前にページを閉じると編集を失うため、離脱時には確認を表示します。外部エディターで変更したファイルは、同じファイルを選び直して再確認できます。ブラウザーからファイルを直接上書きしたり、自動監視したりする機能はありません。

## 実装と検証

- `src/client/`: 3画面・認証画面・QR・WebSocket 再接続。
- `src/worker/`: API、認証、大会ごとの Durable Object、ゲーム進行、D1 永続化。
- `src/shared/`: 公開データ型・問題検証・公開URL生成。
- `migrations/`: 正規化した大会・問題スナップショット・参加者・参加資格・回答。

Durable Object が大会内の操作を直列化し、D1 への保存成功後に受理通知と状態更新を送ります。DO が再起動したら D1 から復元します。初期版は通常の WebSocket 接続を使い、接続中の DO の休止は採用していません。タイマーには DO の alarm を使います。

```sh
npm run check
```

純粋なゲームロジック・認証・URL検証、ローカル workerd による D1 の保存失敗時のロールバックと DO 再生成、Miniflare で40参加者の WebSocket 接続・同時回答・再接続・結果集計を確認します。統合テストは独立した一時DBを使い、15秒の実タイマーを含みます。開発サーバーは不要です。

テーマは [Swift 公式SVG](https://www.swift.org/assets/images/swift.svg) の `#F05138` を基準とし、文字とボタンには読みやすい濃淡を使っています。Swift 公式のサービスではありません。

未実施の項目は、実機スマートフォン・会場回線でのリハーサル、本番 Cloudflare 上の負荷確認、本番デプロイ、結果のエクスポートと保存期間の決定です。詳細は [`docs/spec.md`](docs/spec.md) を参照してください。
